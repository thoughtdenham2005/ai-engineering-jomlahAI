| Requirement — The system SHALL | Scope Boundary — SHALL NOT (where relevant) |
| :--- | :--- |
| **FR 1:** The system shall parse natural language user queries regarding Malaysian destinations to extract travel preferences, target locations, and budget constraints into structured search parameters. | The system shall not process or interpret travel queries targeting locations outside the geographical boundary of Malaysia. |
| **FR 2:** The system shall retrieve factual admission prices, operating hours, and visit duration estimates derived directly from indexed official travel documents and public transit fare guides. | The system shall not generate or display ungrounded cost or schedule estimates when source documentation for a requested location is missing or unavailable. |
| **FR 3:** The system shall allow users to visually add, re-order, connect, and remove travel activity nodes on an interactive flowchart canvas. | The system shall not automatically finalize, lock, or modify node placements without explicit user action on the canvas interface. |
| **FR 4:** The system shall automatically compute and update the total itinerary cost, transit duration, and travel distance across connected nodes whenever the node sequence is modified. | The system shall not execute real-time ticket bookings, process financial payments, or reserve transit seats. |
| **FR 5:** The system shall flag temporal schedule conflicts and display a visual alert whenever an activity node is scheduled outside its documented operating hours or overlaps with transit time. | The system shall not silently allow conflicting node schedules to be saved without presenting a warning to the user. |
