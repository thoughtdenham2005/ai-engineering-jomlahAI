# Project Framing & Application Scope Checkpoint


| System Dimension | Details, Evidence, & Boundaries |
| :--- | :--- |
| **1) Problem Evidence** | **Privacy:** Uploading sensitive travel details to public APIs poses data safety risks ([IATA AI Survey](https://astanatimes.com/2026/10/iata-survey-entry-rules-deter-43-of-travelers-as-ai-biometrics-gain-ground/)).<br><br>**Hallucinations:** Small LLM models in travel apps lack up-to-date data, generating false routes or inaccurate fees ([BBC Travel: AI planning perils](https://www.bbc.com/travel/article/20250926-the-perils-of-letting-ai-plan-your-next-trip)).<br><br>**UX:** Complex layouts with excessive options trigger information overload and user exhaustion (Firmansyah et al., 2023). |
| **2) Existing Approaches** | **Societal Auditing:** Academic systems studying LLM bias and identifying 7 major bias classes in generative itinerary creators (Shizhen et al., 2026).<br><br>**Security:** Intelligent AI Firewalls that monitor conversational traffic, redact PII (like passport numbers), and suppress jailbreak attempts.<br><br>**Interface:** Unified workflow designs that connect desktop web and mobile application tools under one cohesive design system ([Escape App Case Study](https://maverickframe.com/success-stories/escape-travel-app-ui/)). |
| **3) Project / Engineering Gap** | Existing systems depend on rigid sequentially-structured lists and generic chatbots that return outdated, ungrounded, or flat-out fake recommendations due to missing real-time integrations and high error rates in LLM-based itinerary tools. |
| **4) Objective O1** | Design a node-based drag-and-drop flowchart interface in Flutter that visually represents travel itineraries as connected activity nodes, enabling users to customize non-linear trip paths, set activity sequences, and view real-time budget and time updates. |
| **5) Objective O2** | Develop a Python backend integrating a Retrieval-Augmented Generation (RAG) pipeline paired with a graph computation engine to extract accurate local pricing and schedules from official Malaysian tourism PDFs and transit fare cards while dynamic recalculations update total cost, transit duration, and travel distances across connected nodes. |
| **6) Intended Users** | Individual travelers, group planners, and tourists looking for customized visual trip planning in Malaysia. |
| **7) Supported Tasks** | **Task 1:** Visual Itinerary Creation & Customization (placing, rearranging, and mapping activity nodes on a canvas).<br><br>**Task 2:** Verified Destination & Price Querying (retrieving admission costs, opening hours, and recommended durations for sights).<br><br>**Task 3:** Dynamic Budget & Route Computation (estimating transit times, travel distances, and transit fare estimates). |
| **8) Information / Knowledge Domain** | **Geographic:** Restricted exclusively to Malaysia, with a core focus on key tourism hotspots (like Klang Valley, Penang, and Malacca).<br><br>**Metadata:** Landmark pricing (local citizen MyKad vs. standard tourist), schedule calendars, cultural guidelines, and dress codes for sacred spaces.<br><br>**Logistics:** Urban public transit routes (LRT, MRT, Bus), transit fare charts, line patterns, and standard operational frequencies. |
| **9) Operating Context** | High-performance visual desktop web workspaces used during pre-trip brainstorming sessions, alongside mobile application interfaces used on-the-go for active route checking and quick canvas adjustments. |
| **10) Important Constraints** | Fetching and updating live data from dynamic, volatile external websites is highly challenging.<br><br>The local deployment of resource-heavy AI workflows can exhaust device battery and RAM quickly.<br><br>Gaining traveler trust demands rigorous, transparent, and trusted user data privacy safeguards. |
| **11) Explicit Out-of-Scope Tasks** | **Transactions:** Will NOT support or execute actual flight, hotel, or attraction ticket payment transactions.<br><br>**Jurisdiction:** Will NOT supply legal guidance, custom controls advice, or Malaysian visa check details.<br><br>**Falsification:** Will NOT generate, predict, or guess missing information (unverified routes/fees must be clearly flagged). |
| **12) Evaluation Focus** | Verify if the Python-based RAG pipeline delivers $\ge 85\%$ Precision and Recall for landmark pricing and hours, with $0\%$ hallucinations.<br><br>Validate if the Flutter visual canvas and graph engine execute recalculations in $\le 500\text{ ms}$ upon any node manipulation with zero temporal conflicts. |
